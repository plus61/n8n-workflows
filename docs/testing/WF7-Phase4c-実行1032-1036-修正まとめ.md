## 🔧 実装した解決策

### アプローチ1: Fetch Statusのレスポンスから直接動画URLを抽出

**ノード**: `Extract Video URL (Attempt 1)`

ステータスが`COMPLETED`の場合、`Fetch Status`のレスポンスに動画URLが含まれている可能性があります。

**実装内容**:
```javascript
// Fetch Statusのレスポンスから直接動画URLを抽出
const statusData = $input.first().json;

let videoUrl = statusData.output?.video_url
  || statusData.output?.video?.url
  || statusData.output?.url
  || statusData.video_url
  || statusData.result?.video_url
  || statusData.video?.url
  || (statusData.url && !statusData.url.includes('/requests/') && !statusData.url.includes('/status'));

// boolean型に変換（重要！）
const needsGetRequest = Boolean(!videoUrl && statusData.response_url);
```

**メリット**: 追加のHTTPリクエストが不要で高速  
**デメリット**: レスポンスに動画URLが含まれていない場合がある

```javascript
// レスポンスから動画URLを抽出
```

**メリット**: 成功実例で動作確認済み  
**デメリット**: 追加のHTTPリクエストが必要、422エラーが発生する可能性がある

## ⚠️ 重要な修正ポイント

### 1. boolean型への変換

**問題**: `needs_get_request`が文字列になっていた  
**修正**: `Boolean()`を使用して確実にboolean型に変換

```javascript
// ❌ 間違い
const needsGetRequest = !videoUrl && statusData.response_url; // 文字列を返す

// ✅ 正しい
const needsGetRequest = Boolean(!videoUrl && statusData.response_url); // booleanを返す
```

### 2. エラーハンドリング

**問題**: 422エラーが発生するとワークフローが停止していた  
**修正**: `neverError: true`を設定して、エラーでも処理を続行

```javascript
// Get Result (Approach 2)ノードの設定
options: {
  response: {
    response: {
      neverError: true  // 422エラーでも処理を続行
    }
  }
}
```

### 3. エラーメッセージの改善

**問題**: エラーの詳細が不明確だった  
**修正**: 詳細なエラーメッセージとデバッグ情報を追加

```javascript
// Merge Video URLノードで詳細なエラーメッセージを返す
throw new Error(
  'Video URL not found in both approaches.\n' +
  'Attempt 1 (status response): ' + JSON.stringify(errorDetails.attempt1, null, 2) + '\n' +
  'Attempt 2 (response_url GET): ' + JSON.stringify(errorDetails.attempt2, null, 2)
```
