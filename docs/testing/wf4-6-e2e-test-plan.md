# WF4-6 E2Eテストプラン

## 概要

このドキュメントでは、コンテンツ自動化パイプライン（WF4→WF5→WF6）のE2Eテストシナリオを定義します。

## テスト対象ワークフロー

### WF4: note記事検出システム (ALgOQnXrVf0enb9B)
- **トリガー**: スケジュール（15分ごと）
- **機能**: note.com/61beef/rss から新着記事を検出してNotion DBに保存
- **出力**: Notion DB `29968d5c-2986-81ad-90d0-c24ed710503e` に記事データ

### WF5: トピック抽出AI (NsNt4wxzGWj19OqN)
- **トリガー**:
  - スケジュール（水・土 9:00）
  - 手動トリガー（テスト用）
- **機能**: 過去30日の人気記事からGPT-4でトピック抽出
- **入力**: Notion DB `29968d5c-2986-81ad-90d0-c24ed710503e` から記事データ
- **出力**: Notion DB `29968d5c-2986-81d7-8a8b-e921a0e06a9a` にトピックデータ

### WF6: note記事自動生成（AI）(pIj6S24Qg7O501PX)
- **トリガー**:
  - スケジュール（毎日 10:00）
  - 手動トリガー（テスト用）
- **機能**: トピックDBから最高スコアのトピックを選択し、GPT-4で記事生成
- **入力**: Notion DB `29968d5c-2986-81d7-8a8b-e921a0e06a9a` からトピックデータ
- **出力**: Notion DB `29968d5c-2986-81ad-90d0-c24ed710503e` に生成記事を保存

## テスト前提条件

### 1. Notion DB状態確認
- **記事DB** (`29968d5c-2986-81ad-90d0-c24ed710503e`)
  - WF4で検出された記事が存在すること
  - ステータスが「検知済み」または「分析済み」の記事があること
  - viewCount, likeCount のメトリクスが記録されていること

- **トピックDB** (`29968d5c-2986-81d7-8a8b-e921a0e06a9a`)
  - WF5で抽出されたトピックが存在すること（任意）
  - 新規トピック生成をテストする場合は、既存トピックの状態を記録

### 2. API接続確認
- n8n インスタンス: `https://n8n-python-production-344b.up.railway.app/` が稼働中
- Notion API: 認証情報が有効
- OpenAI GPT-4 API: 認証情報が有効、クォータ残量あり
- RSS Feed: `https://note.com/61beef/rss` がアクセス可能

### 3. 環境変数確認
```bash
# n8n環境変数
NOTION_API_KEY=<検証>
OPENAI_API_KEY=<検証>
```

## E2Eテストシナリオ

### シナリオ1: 完全自動実行テスト（本番相当）

**目的**: スケジュールトリガーによる自動実行の動作確認

**手順**:
1. **WF4実行待機** (15分間隔)
   - 次回実行時刻を確認
   - 実行完了まで待機
   - Notion記事DBに新規記事が追加されたか確認

2. **WF5実行待機** (水・土 9:00)
   - ※テストタイミングによっては手動トリガーに切り替え（シナリオ2参照）

3. **WF6実行待機** (毎日 10:00)
   - ※テストタイミングによっては手動トリガーに切り替え（シナリオ2参照）

**検証ポイント**:
- WF4: 新着記事が正しくNotionに保存される
- WF5: 記事分析→トピック抽出→Notion保存が成功
- WF6: トピック選択→記事生成→Notion保存が成功

### シナリオ2: 手動トリガーによる即時テスト（推奨）

**目的**: 即座にWF5→WF6のフローを検証

**前提条件**:
- WF4で既に記事がNotion DBに保存されている状態
- 記事のステータスが「検知済み」または「分析済み」
- 記事のviewCount/likeCountが入力されている

**手順**:

#### Step 1: WF4の状態確認
```bash
# n8n MCPでWF4の最終実行を確認
# 記事DBの最新データを確認
```

**確認項目**:
- [ ] 記事DBに過去30日以内の記事が存在する
- [ ] 記事のステータスが「検知済み」または「分析済み」
- [ ] viewCount ≥ 0, likeCount ≥ 0 のデータが存在

#### Step 2: WF5手動実行（トピック抽出）
```bash
# n8n UI: Workflows > WF5 (NsNt4wxzGWj19OqN)
# 「Test workflow」をクリック
# Manual Trigger ノードから実行
```

**実行後の確認**:
- [ ] WF5が正常完了（エラーなし）
- [ ] GPT-4 APIが正常に呼び出された
- [ ] トピックDBに新規トピックが作成された
- [ ] トピックデータ構造確認:
  ```json
  {
    "キーワード": ["keyword1", "keyword2", ...],
    "ニーズ推定": "...",
    "提案トピック": ["topic1", "topic2", ...],
    "スコア": <number>,
    "ステータス": "アクティブ"
  }
  ```

#### Step 3: WF6手動実行（記事生成）
```bash
# n8n UI: Workflows > WF6 (pIj6S24Qg7O501PX)
# 「Test workflow」をクリック
# Manual Trigger ノードから実行
```

**実行後の確認**:
- [ ] WF6が正常完了（エラーなし）
- [ ] トピックDBから最高スコアのトピックが選択された
- [ ] GPT-4でタイトル3種（howto, question, story）が生成された
- [ ] タイトル優先度ソートが正しく動作（howto > question > story）
- [ ] GPT-4で本文（3000-5000文字）が生成された
- [ ] 記事DBに新規記事が作成された
- [ ] 記事データ構造確認:
  ```json
  {
    "タイトル": "...",
    "本文": "...",
    "ステータス": "下書き",
    "トピック参照": <topic_id>,
    "生成日時": "..."
  }
  ```
- [ ] Slack通知が送信された

### シナリオ3: エラーハンドリングテスト

**目的**: 異常系の動作確認

**テストケース**:

1. **WF5: 記事データなし**
   - 前提: Notion記事DBを空にする or 過去30日以内の記事をすべて削除
   - 期待結果: WF5がエラーなく完了（トピック生成なし）

2. **WF5: GPT-4 APIエラー**
   - 前提: OpenAI APIキーを無効化 or クォータ超過状態
   - 期待結果: WF5がエラーで停止、エラーログに詳細が記録

3. **WF6: トピックDBが空**
   - 前提: トピックDBをすべて非アクティブ化
   - 期待結果: WF6がエラーなく完了（記事生成なし）

4. **WF6: GPT-4 APIエラー**
   - 前提: OpenAI APIキーを無効化 or クォータ超過状態
   - 期待結果: WF6がエラーで停止、エラーログに詳細が記録

## トラブルシューティング

### WF4が記事を検出しない
- RSS Feedのアクセス確認: `curl https://note.com/61beef/rss`
- Notion DBの重複チェックロジック確認
- スケジュール設定確認（15分間隔）

### WF5でトピックが生成されない
- Notion記事DBのデータ確認（過去30日以内、ステータス）
- GPT-4 APIキー確認
- GPT-4プロンプト確認（Function - プロンプト構築ノード）

### WF6で記事が生成されない
- トピックDBのアクティブトピック確認
- GPT-4 APIクォータ確認
- タイトル選択ロジック確認（Function - タイトル選択ノード）

### Notion DBへの保存失敗
- Notion APIキー確認
- データベースID確認:
  - 記事DB: `29968d5c-2986-81ad-90d0-c24ed710503e`
  - トピックDB: `29968d5c-2986-81d7-8a8b-e921a0e06a9a`
- Notionのプロパティスキーマ確認
