## 🎯 1. 上位目的との関連

### MEOプロジェクトにおける位置づけ

**最終目標**: AI自走改善ループ稼働
- **タスクVの役割**: PDCAサイクルの「Check → Action提案」を完全自動化
- **狙い**: 人間の介入なしで、データ分析→改善提案→次の施策決定

### Phase4全体の文脈

```
タスクU（KPI統合） → データ収集・可視化
   ↓
タスクV（AIレポート）← 今回 | 分析・改善提案
   ↓
タスクW（人気記事再配信）→ 自動実行
   ↓
タスクX（トピック再学習）→ 学習サイクル完成
```

**タスクVが無いと**: データは見えても、次のアクションを人間が考える必要がある
**タスクVがあると**: AIが自動で分析→改善提案→次のアクション指示

## 📊 2. ビジネス要件

### 解決したい課題

| 課題 | 現状（Phase3まで） | 理想（Phase4） | タスクVの解決 |
|------|-------------------|---------------|---------------|
| **分析工数** | 週5時間の手動分析 | 完全自動化 | GPT-4が自動分析 |
| **改善提案** | 経験則に依存 | データ駆動 | AIが客観的に提案 |
| **施策決定** | 意思決定に時間 | 即座に実行 | 優先度付きで提案 |
| **PDCA速度** | 週1回 | 日次または時間単位 | リアルタイム化 |

### ビジネス価値

**定量的効果**:
- 分析工数: 週5時間 → 0時間（**年260時間削減**）
- PDCA速度: 週1回 → 日次（**7倍高速化**）
- 改善提案精度: 経験則 → データ駆動（**客観性向上**）

**定性的効果**:
- 人間は戦略思考に集中可能
- データに基づく意思決定文化の確立
- 属人性の排除

## 🛠️ 3. 機能要件

### 3.1 コア機能

#### F1: 自動データ収集
- **入力**: タスクU（KPI統合）のダッシュボードデータ
- **収集項目**:
  - PV数（日次・週次・月次）
  - CV数、CVR
  - LINE友だち数、開封率、クリック率
  - note記事数、人気記事ランキング
  - SNS投稿数、エンゲージメント率
  - デモ予約数、成約数、成約率
- **頻度**: 日次（毎日9:00）+ 週次（月曜9:00）+ 月次（1日9:00）

#### F2: AI分析・レポート生成
- **分析内容**:
  1. **KPI達成度評価**
     - 目標PV 22,300 に対する進捗
     - CVR 30% に対する進捗
     - 前週比・前月比の変化率

  2. **トレンド分析**
     - PV推移の傾向（上昇/下降/横ばい）
     - CVR推移の傾向
     - 人気コンテンツの特定

  3. **問題点の特定**
     - 目標未達の場合の原因分析
     - ボトルネックの特定
     - 異常値の検知

  4. **改善提案の生成**
     - 優先度付き施策リスト（Top 3-5）
     - 各施策の期待効果
     - 実行難易度の評価

- **GPT-4プロンプト設計**:
```
あなたはMEO集客自動化プロジェクトのデータアナリストです。
以下のKPIデータを分析し、改善提案を行ってください。

【KPIデータ】
- PV: {current_pv} / 目標22,300 ({achievement_rate}%)
- CVR: {current_cvr}% / 目標30%
- LINE友だち: {line_friends}人
- note記事: {note_articles}本
...（その他データ）

【分析観点】
1. 目標達成度の評価
2. 前週比・前月比のトレンド分析
3. 問題点・ボトルネックの特定
4. 改善提案（優先度順、Top 5）

【出力形式】
以下の構造化されたMarkdown形式で出力してください：
## 📊 KPI達成度サマリー
## 📈 トレンド分析
## ⚠️ 問題点・ボトルネック
## 💡 改善提案（優先度順）
### 提案1: [タイトル]
- 期待効果: ...
- 実行難易度: ...
- 推奨実施時期: ...
```

#### F3: レポート配信
- **配信先**:
  - Notion（専用ページ自動作成）
  - LINE（サマリー通知）
  - メール（詳細レポート添付）

- **配信タイミング**:
  - 日次レポート: 毎日9:30（分析完了後）
  - 週次レポート: 月曜10:00
  - 月次レポート: 1日10:00

- **レポート形式**:
  - Markdown（Notion用）
  - PDF（メール添付用）
  - テキスト（LINE通知用）

#### F4: アクション連携
- **自動実行トリガー**:
  - タスクW（人気記事再配信）への指示
  - タスクX（トピック再学習）への指示
  - 新規施策の提案（手動確認後に実行）

- **連携フロー**:
```
AIレポート生成
   ↓
改善提案の分類
   ↓
├─ 自動実行可能 → タスクW/Xへ指示
└─ 手動確認必要 → 通知 → 承認 → 実行
```

## 🔧 4. 技術要件

### 4.1 技術スタック

| コンポーネント | 技術 | 役割 |
|---------------|------|------|
| **ワークフロー** | n8n | 全体のオーケストレーション |
| **データ収集** | n8n + HTTP Request | タスクUのAPIからデータ取得 |
| **AI分析** | GPT-4 API | データ分析・レポート生成 |
| **データ保存** | Notion API | レポート保存・履歴管理 |
| **通知** | LINE Messaging API | サマリー通知 |
| **PDF生成** | Puppeteer / PDF.co | PDF形式レポート生成 |

### 4.2 n8nワークフロー設計

#### メインワークフロー: 「AIレポート自動生成（日次）」

```yaml
nodes:
  1. Schedule Trigger:
      cron: "0 9 * * *"  # 毎日9:00
      timezone: "Asia/Tokyo"

  2. HTTP Request - KPIデータ取得:
      method: GET
      url: "{{タスクUのAPIエンドポイント}}"
      authentication: Bearer Token

  3. Function - データ整形:
      code: |
        // KPIデータを整形
        const data = items[0].json;
        return [{
          json: {
            current_pv: data.pv.current,
            target_pv: 22300,
            achievement_rate: (data.pv.current / 22300 * 100).toFixed(1),
            current_cvr: data.cvr.current,
            target_cvr: 30,
            ...
          }
        }];

  4. GPT-4 - AI分析:
      model: "gpt-4"
      temperature: 0.3
      max_tokens: 2000
      prompt: "{{上記のプロンプトテンプレート}}"

  5. Function - レポート構造化:
      code: |
        // GPT-4の出力をパース
        const report = items[0].json.choices[0].message.content;
        // 改善提案を抽出
        const proposals = extractProposals(report);
        return [{
          json: {
            report_markdown: report,
            proposals: proposals,
            generated_at: new Date().toISOString()
          }
        }];

  6. Notion - レポート保存:
      operation: "Create Page"
      database_id: "{{レポートDB_ID}}"
      properties:
        Title: "日次レポート {{date}}"
        Content: "{{report_markdown}}"
        Generated_At: "{{generated_at}}"

  7. LINE Notify - サマリー通知:
      message: |
        📊 日次レポート完了

        【KPI達成度】
        PV: {{achievement_rate}}%
        CVR: {{current_cvr}}%

        【Top改善提案】
        1. {{proposal_1}}
        2. {{proposal_2}}

        詳細: {{notion_url}}

  8. IF - 自動実行判定:
      condition: "{{proposals.auto_executable}}"
      true: → Node 9
      false: → End

  9. HTTP Request - タスクW/X連携:
      method: POST
      url: "{{タスクW/Xのwebhook}}"
      body: "{{auto_proposals}}"
```

#### 週次・月次ワークフロー

週次・月次は同じ構造で、以下のみ変更：
- データ集計期間（日次→週次→月次）
- GPT-4プロンプト（分析深度を上げる）
- レポート配信先（週次・月次はメールPDFも追加）

### 4.3 GPT-4 API設定

```yaml
model: "gpt-4-turbo"  # または最新モデル
temperature: 0.3  # 一貫性重視
max_tokens: 2500  # レポート長に応じて調整
response_format: "markdown"
```

### 4.4 エラーハンドリング

```yaml
error_handling:
  - KPIデータ取得失敗:
      retry: 3回（指数バックオフ）
      fallback: 前日データで代替 + アラート通知

  - GPT-4 API失敗:
      retry: 3回
      fallback: 簡易レポート生成（テンプレート） + アラート通知

  - Notion保存失敗:
      retry: 3回
      fallback: Google Sheetsに保存 + アラート通知

  - LINE通知失敗:
      retry: 3回
      fallback: メール通知 + エラーログ
```

|-----|--------|------|--------|--------|------|

## 📈 トレンド分析

### PV推移
- 週次: +8.8%（先週17,000 → 今日18,500）
- 月次: +23.3%（先月15,000 → 今日18,500）
- **傾向**: 順調に増加中、目標まで残り3,800PV

### CVR推移
- 週次: +6.3%（先週24.0% → 今日25.5%）
- 月次: +15.9%（先月22.0% → 今日25.5%）
- **傾向**: 改善傾向だが、目標30%まで残り4.5%

### 人気コンテンツ
1. 「英語学童の選び方」（850PV、CV15件）
2. 「バイリンガル教育のメリット」（720PV、CV12件）
3. 「英語学童の費用比較」（680PV、CV10件）

## ⚠️ 問題点・ボトルネック

### 1. PV目標未達（-17%）
- **原因**: note記事投稿ペースが週8本（目標10本）に届いていない
- **影響**: 週次目標から約400PV不足

### 2. CVR微減（前日比-1.9%）
- **原因**: LINEステップ配信の開封率が45%→42%に低下
- **影響**: CV機会損失（推定3件/日）

### 3. SNSエンゲージメント低迷
- **現状**: 3.2%（目標5.0%）
- **原因**: 投稿時間帯が最適化されていない可能性

## 💡 改善提案（優先度順）

### 🔥 提案1: 人気記事の再配信強化
- **期待効果**: PV +500-800/日、CV +5-8件/日
- **実行難易度**: 低（タスクWで自動実行可能）
- **推奨実施時期**: 即時
- **具体的アクション**:
  - 「英語学童の選び方」を週2回再配信（火・金）
  - SNS同時投稿で拡散
  - LINE配信リストに追加

### ⚡ 提案2: LINEステップ配信の改善
- **期待効果**: 開封率 42%→50%、CVR +2-3%
- **実行難易度**: 中（コンテンツ見直し必要）
- **推奨実施時期**: 3日以内
- **具体的アクション**:
  - 件名のA/Bテスト実施
  - 配信時間を19:00→20:00に変更テスト
  - 初回配信の内容を簡潔化

### 📊 提案3: note投稿ペース回復
- **期待効果**: PV +400-600/週
- **実行難易度**: 低（タスクI自動化済み）

- **具体的アクション**:
  - トピック抽出AI（タスクG）の実行頻度を週2回→週3回に増加
  - 週末に2本追加投稿

### 🎯 提案4: SNS投稿時間最適化
- **期待効果**: エンゲージメント率 3.2%→5.0%
- **実行難易度**: 低（スケジュール変更のみ）
- **推奨実施時期**: 明日から
- **具体的アクション**:
  - X投稿: 12:00 → 20:00-21:00に変更

### 💡 提案5: デモ予約→成約の強化

## ✅ 7. 品質要件（NFR: Non-Functional Requirements）

### 7.1 パフォーマンス

| 指標 | 目標値 |
|------|--------|
| レポート生成時間 | 日次: 3分以内、週次: 5分以内、月次: 10分以内 |
| GPT-4レスポンス時間 | 30秒以内 |
| Notion保存時間 | 10秒以内 |
| LINE通知遅延 | レポート完了から30秒以内 |

### 7.2 可用性

- **稼働率**: 99.5%以上（月間ダウンタイム <3.6時間）
- **障害時の対応**: 自動リトライ3回 + フォールバック
- **データ損失**: ゼロ（Notion保存失敗時はGoogle Sheetsバックアップ）

### 7.3 拡張性

- **データ量増加**: 1年分のレポート履歴保存（365日 + 52週 + 12ヶ月 = 429レポート）
- **KPI項目追加**: 最大50項目まで対応
- **GPT-4プロンプト変更**: 簡単にカスタマイズ可能

### 7.4 保守性

- **ログ記録**: 全実行ログをn8nに保存（30日間）
- **エラー通知**: 即時LINE + メール
- **設定変更**: n8nワークフロー画面で容易に変更可能

### 7.5 セキュリティ

- **APIキー管理**: n8n環境変数で管理（平文保存禁止）
- **データアクセス**: Notion Integrationで最小権限の原則
- **通信暗号化**: 全API通信HTTPS必須
