## 🚀 ワークフロー作成

### パターン1: ゼロから新規ワークフロー作成

**状況**: 新しいワークフローを最初から作りたい

**推奨プロンプト**:

```
@mcp-sequential-thinking
@n8n-workflows-docs
@n8n-mcp

以下のワークフローを作成したいです。最適なアプローチを段階的に考えて実装してください。

【要件】
目的: [具体的な目的を記述]
トリガー: [Webhook/Scheduled/Manual]
処理内容: [処理の詳細]
使用サービス: [LINE, Notion, Slackなど]

【手順】
1. Sequential Thinkingで設計を段階的に考える
   - 類似のワークフロー例を探す
   - 最適なノード構成を検討
   - エラーハンドリング戦略を立てる

2. n8n-workflows-docsで参考例を探す
   - 類似のパターンを検索
   - ベストプラクティスを確認

3. n8n-mcpで実装
   - ノードを作成
   - 接続を設定
   - テスト実行

4. バリデーションと最適化
```

**具体例**:

```
@mcp-sequential-thinking
@n8n-workflows-docs
@n8n-mcp

以下のワークフローを作成したいです：

【要件】
目的: LINE友だち追加時に自動的にNotionデータベースに記録し、Slackに通知
トリガー: Webhook（LINEから）
処理内容:
  1. LINEのWebhookを受信
  2. 友だち情報を抽出（userId, displayName, timestamp）
  3. Notionの「リード管理」データベースに新規ページ作成
  4. Slackの#新規リードチャネルに通知
  5. エラー時はSlackの#エラー通知チャネルに送信

使用サービス: LINE Messaging API, Notion API, Slack API

【依頼】
1. まず類似のワークフローパターンをZie619から探して
2. 最適なノード構成を提案
3. n8n-mcpで実装
4. エラーハンドリングも含めて完成させて
```

## 🎯 プロンプト作成のベストプラクティス

### 1. 適切なMCPの選択

```
✅ 推奨:
- 目的に応じて必要なMCPのみを指定
- @mcp-sequential-thinking: 複雑な思考が必要な時
- @n8n-workflows-docs: 参考例を探す時
- @n8n-mcp: 実装・変更する時

❌ 避ける:
- 全てのMCPを毎回指定
- 無関係なMCPの指定
```

### 2. コンテキストの明確化

```
✅ 推奨:
【明確な要件】
- 目的を具体的に
- 現状を説明
- 期待する結果を記述

❌ 避ける:
- 曖昧な依頼
- コンテキスト不足
```

### 3. 段階的なアプローチ

```
✅ 推奨:
1. まず調査・分析
2. 次に設計
3. そして実装
4. 最後に検証

❌ 避ける:
- いきなり実装を依頼
- 検証なしで本番適用
```

### 4. 参照の活用

```
✅ 推奨:
- 既存のワークフローIDを提供
- 関連ドキュメントを参照
- 類似例の検索を依頼

❌ 避ける:
- ゼロから全て作る
- 既存リソースを無視
```
