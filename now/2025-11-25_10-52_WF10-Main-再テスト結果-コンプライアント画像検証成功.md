## 🔍 重大な発見

### 発見1: n8n 状態管理アーキテクチャの理解

n8n は2つの独立した状態を管理している：

1. **データベースメタデータ**（n8n MCP API が返す）:
   - `active: false, isArchived: true`
   - 永続化された状態情報
   - **Stale になる可能性あり**

2. **Runtime 状態**（Railway ログと実際の動作）:
   - ワークフロー JSON の `"active"` フィールドから読み込み
   - 起動時にアクティブ化される
   - **実際の Webhook 受信可否はこちらに依存**

**重要な理解**:
- n8n は起動時にワークフロー JSON を読み込み、`"active": true` の場合はアクティブ化する
- データベースメタデータが `active: false` でも Runtime がアクティブなら Webhook は動作する
- **Railway ログの "Activated workflow" メッセージは Runtime 状態を示す**
- **実際の動作確認は Webhook テストで行うべき**

## 📝 技術的知見

### n8n ワークフローアクティブ化メカニズム

**方法1: ワークフロー JSON で制御**（推奨）
```json
{
  "name": "Workflow Name",
  "active": true,
  "nodes": [...],
  "connections": {...}
}
```
- n8n にインポート/アップロード
- n8n 起動時に自動的にアクティブ化
- **検証**: Railway ログで "Activated workflow" メッセージを確認

**方法2: n8n UI で手動アクティブ化**
- n8n Web UI でトグルスイッチを操作
- データベースメタデータも更新される

**方法3: n8n API で制御**（制限あり）
- `n8n_update_full_workflow(active=true)` は効果が限定的
- `n8n_update_partial_workflow` での activateWorkflow 操作はサポート外の可能性

### kie.ai API コンテンツポリシー

**禁止コンテンツ**:
- ❌ Photorealistic people（写実的な人物）
- ❌ 人物が含まれる画像

**許可コンテンツ**:
- ✅ 風景（mountains, beaches, forests）
- ✅ 物体（objects, products, architecture）
- ✅ 抽象的なビジュアル（patterns, textures）

**検証方法**:
- HTTP 400 エラー → コンテンツポリシー違反の可能性
- HTTP 200 OK + taskId → 受理された

### n8n Wait Node のベストプラクティス

**外部API非同期処理の場合**:
- Wait 時間は API の推定処理時間の 2-3 倍を設定
- kie.ai の場合: 推定 4-5 分 → Wait 10 分（600秒）が適切
- Loop 構造で複数回チェックする設計にする
