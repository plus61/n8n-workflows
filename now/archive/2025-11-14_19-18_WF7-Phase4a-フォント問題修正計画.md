# WF7 Phase4a フォント問題修正計画

**作成日時**: 2025-11-14 19:18:08 JST
**対象**: WF7 Phase4a - Pillow画像生成
**問題**: フォント読み込み失敗による黒画像生成
**影響範囲**: Phase4a → Phase4b → Phase4c 全体（最終動画が完全に空白）

---

## 🔍 問題の詳細

### 現象
- 最終動画（80秒）が完全に空白
- Phase4c（動画結合）は正常動作
- Phase4b（FFmpeg動画化）は正常動作
- **Phase4a（Pillow画像生成）が黒画像を生成**

### 実測データ

**Phase4a生成画像の分析結果**:
```
画像URL: https://res.cloudinary.com/drzmodro8/image/upload/v1763104807/n8n_meo_wf7_slide/wklgg0yw62uai1a9yexm.png
画像サイズ: 1080x1920
ファイルサイズ: 11,871 bytes (異常に小さい)

色分布:
- RGB(26, 26, 46): 99.97% (2,072,967ピクセル) ← 背景色
- RGB(255, 255, 255): 0.00% (24ピクセルのみ) ← テキスト色
- ユニークな色数: 181色 (正常なら数千色)
- 平均輝度: 32.69/255 (非常に暗い)
```

**期待値との比較**:
- 期待ファイルサイズ: 50-500KB（コンテンツあり）
- 実際: 11.8KB
- 期待白色ピクセル: 数万ピクセル（テキスト部分）
- 実際: 24ピクセル（0.00%）

## 🎯 根本原因

### コード分析結果

**ファイル**: `/workflows/wf7-video-renderer/phase4a_code_node_fixed.py`

#### 1. フォントパス設定（Lines 7-9）
```python
FONT_PATH = "/usr/share/fonts/truetype/noto/NotoSansJP-Regular.ttf"
FONT_BOLD_PATH = "/usr/share/fonts/truetype/noto/NotoSansJP-Bold.ttf"
```
**問題**: Railway環境でこれらのパスが存在しない可能性

#### 2. エラーハンドリング（Lines 41-52）
```python
try:
    font_main = ImageFont.truetype(FONT_PATH, 70)
    font_label = ImageFont.truetype(FONT_PATH, 40)
    font_icon = ImageFont.truetype(FONT_PATH, 120)
except Exception as e:
    print(f"フォント読み込みエラー: {e}")  # ← n8nログに表示されない
    font_main = ImageFont.load_default()
    font_label = ImageFont.load_default()
    font_icon = ImageFont.load_default()
```
**問題**:
- エラーが `print()` のみで出力（n8nログに表示されない）
- デフォルトフォントへのフォールバック
- デフォルトフォントは日本語レンダリング不可

#### 3. 背景色設定（Lines 37-38）
```python
bg_color = hex_to_rgb(brand_colors.get('background', '#1a1a2e'))
img = Image.new('RGB', (1080, 1920), color=bg_color)
```
**結果**: RGB(26, 26, 46)の背景色 = 実測データの99.97%と一致

#### 4. テキスト描画（Lines 73-76）
```python
draw.multiline_text((x+3, y+3), wrapped, fill="#000000", font=font_main, align="center")  # 影
primary_text_color = hex_to_rgb(brand_colors.get('primary_text', '#ffffff'))
draw.multiline_text((x, y), wrapped, fill=primary_text_color, font=font_main, align="center")  # テキスト
```
**期待**: 白色テキスト（#ffffff）+ 黒色影
**実際**: テキストが描画されない（デフォルトフォントで日本語レンダリング失敗）

### 原因の連鎖

```
1. Railway環境でフォントファイルが存在しない
   ↓
2. ImageFont.truetype() が例外を投げる
   ↓
3. printでエラー出力（n8nでは見えない）
   ↓
4. ImageFont.load_default() にフォールバック
   ↓
5. デフォルトフォントは日本語文字を描画できない
   ↓
6. テキスト描画が失敗（サイレントに）
   ↓
7. 背景色のみの画像（99.97%黒）が生成
   ↓
8. Phase4b → FFmpegで黒画像を動画化
   ↓
9. Phase4c → 7本の黒動画を結合
   ↓
10. 最終結果: 80秒の完全空白動画
```

## 🛠️ 修正方法（オプション比較）

### オプションA: Railway Dockerfileでフォントインストール ⭐ 推奨

**概要**: Railway環境のDockerfileにNoto Sans JPフォントをインストール

**メリット**:
- ✅ システムレベルでの恒久的な解決
- ✅ 他のコンポーネントでも日本語フォント利用可能
- ✅ 既存コード変更不要（フォントパスそのまま）
- ✅ パフォーマンス最適（ローカルファイル読み込み）

**デメリット**:
- ❌ Dockerfileの修正が必要
- ❌ Railway再デプロイが必要（数分のダウンタイム）

**実装難易度**: 中（Dockerfile編集経験必要）

**実装例**:
```dockerfile
# Dockerfile.fastapi に追加
RUN apt-get update && apt-get install -y \
    fonts-noto-cjk \
    && rm -rf /var/lib/apt/lists/*
```

---

### オプションB: リポジトリにフォントファイルを同梱

**概要**: NotoSansJP-*.ttfファイルをリポジトリに追加し、相対パスで読み込み

**メリット**:
- ✅ 環境に依存しない（どこでも動作）
- ✅ デプロイ時に確実にフォント利用可能
- ✅ バージョン管理可能

**デメリット**:
- ❌ リポジトリサイズ増加（約2-4MB/フォント）
- ❌ コード変更必要（フォントパス修正）
- ❌ ライセンス確認必要（SIL Open Font Licenseは商用利用可）

**実装難易度**: 低

**実装例**:
```python
# phase4a_code_node_fixed.py
import os

# フォントファイルをプロジェクト内に配置
FONT_DIR = os.path.join(os.path.dirname(__file__), "fonts")
FONT_PATH = os.path.join(FONT_DIR, "NotoSansJP-Regular.ttf")
FONT_BOLD_PATH = os.path.join(FONT_DIR, "NotoSansJP-Bold.ttf")
```

---

### オプションC: URLからフォントダウンロード

**概要**: 起動時またはキャッシュにフォントをHTTPダウンロード

**メリット**:
- ✅ リポジトリサイズ不変
- ✅ Dockerfile変更不要
- ✅ フォント更新が容易

**デメリット**:
- ❌ 初回起動が遅い
- ❌ ネットワーク依存（オフライン時動作不可）
- ❌ キャッシュ管理が複雑
- ❌ 外部依存追加（CDN障害リスク）

**実装難易度**: 高

**実装例**:
```python
import requests
import tempfile

def download_font(url, cache_path):
    if not os.path.exists(cache_path):
        r = requests.get(url)
        with open(cache_path, 'wb') as f:
            f.write(r.content)
    return cache_path

FONT_URL = "https://github.com/googlefonts/noto-cjk/raw/main/Sans/OTF/Japanese/NotoSansJP-Regular.otf"
FONT_PATH = download_font(FONT_URL, "/tmp/NotoSansJP-Regular.otf")
```

### オプションD: エラーハンドリング改善のみ

**概要**: フォント読み込み失敗時にn8nエラーとして通知

**メリット**:
- ✅ 問題を早期発見可能
- ✅ 実装が簡単

**デメリット**:
- ❌ 根本解決にならない（画像は生成されない）

**実装難易度**: 最低

**実装例**:
```python
try:

```

**用途**: 他のオプションと併用して、フォント問題の早期検出に使用

**検証スクリプト**: `/workflows/wf7-video-renderer/verify_phase4a_output.py`
```python
#!/usr/bin/env python3
import requests
from PIL import Image
import numpy as np
from io import BytesIO

def verify_image(image_url):
    # 画像ダウンロード
    response = requests.get(image_url)
    img = Image.open(BytesIO(response.content))
    img_array = np.array(img)

    # 統計分析
    brightness = img_array.mean()
    unique_colors = len(np.unique(img_array.reshape(-1, 3), axis=0))

    # 背景色の割合（RGB 26,26,46）
    bg_pixels = np.sum((img_array == [26, 26, 46]).all(axis=2))
    total_pixels = img_array.shape[0] * img_array.shape[1]
    bg_ratio = (bg_pixels / total_pixels) * 100

    # 白色ピクセル数（RGB 255,255,255）
    white_pixels = np.sum((img_array == [255, 255, 255]).all(axis=2))
    white_ratio = (white_pixels / total_pixels) * 100

    print(f"画像URL: {image_url}")
    print(f"サイズ: {img.size}")
    print(f"平均輝度: {brightness:.2f}/255")
    print(f"ユニーク色数: {unique_colors}")
    print(f"背景色比率: {bg_ratio:.2f}%")
    print(f"白色ピクセル比率: {white_ratio:.2f}%")

    # 合格判定
    if bg_ratio < 90 and white_ratio > 1 and unique_colors > 1000:
        print("✅ テスト合格: テキストが正常に描画されています")
        return True
    else:
        print("❌ テスト失敗: テキストが描画されていません")
        return False

# 使用例
image_url = "YOUR_PHASE4A_IMAGE_URL_HERE"
verify_image(image_url)
```

**合格基準**:
- ✅ 背景色比率 < 90% （テキスト領域がある）
- ✅ 白色ピクセル比率 > 1% （テキストが描画されている）
- ✅ ユニーク色数 > 1000 （アンチエイリアス等で色の変化がある）
- ✅ ファイルサイズ > 30KB （コンテンツがある）
