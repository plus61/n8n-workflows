# Cloudinary環境変数設定手順

**作成日時**: 2025-11-15 00:59:12 JST
**対象**: WF7 Phase4a Cloudinaryアップロード機能
**Railway Service**: `fastapi-server`

---

## 📋 概要

Phase4a/4b設計不一致問題を解決するため、Phase4aエンドポイントにCloudinaryアップロード機能を追加しました。これにより、Phase4a→4bの自動パイプライン処理が可能になります。

**実装内容**:
- Phase4aエンドポイント（`/generate-slide`）がCloudinaryに画像をアップロード
- レスポンスに`image_url`フィールドを追加（Phase4b互換）
- `imageData`（base64）も継続サポート（後方互換性）

---

## 🔧 必要な環境変数

Phase4aのCloudinaryアップロード機能を動作させるには、以下の3つの環境変数をRailway `fastapi-server` サービスに設定する必要があります：

### 環境変数一覧

| 変数名 | 説明 | 取得方法 |
|--------|------|----------|
| `CLOUDINARY_CLOUD_NAME` | CloudinaryのCloud Name | Cloudinaryダッシュボード > Settings > Account |
| `CLOUDINARY_API_KEY` | CloudinaryのAPI Key | Cloudinaryダッシュボード > Settings > API Keys |
| `CLOUDINARY_API_SECRET` | CloudinaryのAPI Secret | Cloudinaryダッシュボード > Settings > API Keys |

---

## 🚀 Railway環境変数設定手順

### 1. Railwayダッシュボードにアクセス

```bash
railway open --service fastapi-server
```

または、直接 https://railway.app にアクセスしてプロジェクトを開く

### 2. 環境変数を追加

1. `fastapi-server` サービスを選択
2. **Variables** タブをクリック
3. 以下の3つの環境変数を追加：

```
CLOUDINARY_CLOUD_NAME=<your-cloud-name>
CLOUDINARY_API_KEY=<your-api-key>
CLOUDINARY_API_SECRET=<your-api-secret>
```

### 3. サービスを再デプロイ

環境変数を追加後、Railway が自動的に再デプロイを開始します。手動でトリガーする場合：

```bash
railway up --service fastapi-server
```

または

```bash
railway redeploy --service fastapi-server
```


## ✅ 動作確認

環境変数設定後、Phase4aエンドポイントをテストして、Cloudinaryアップロードが正常に動作することを確認します。

### テスト実行例

```bash
curl -X POST https://fastapi-server-production-dc2b.up.railway.app/generate-slide \
  -H "Content-Type: application/json" \
  -d '{
    "section": "hook",
    "text": "Test slide generation",
    "duration": 5,
    "script_id": "test-cloudinary-001"
  }'
```

**期待されるレスポンス**:
```json
{
  "success": true,
  "section": "hook",
  "duration": 5,
  "image_url": "https://res.cloudinary.com/xxx/image/upload/v123/wf7-slides/test-cloudinary-001/hook.png",
  "imageData": "<base64-data>",
  "image_size_bytes": 42000,
  "script_id": "test-cloudinary-001",
  "filename": "slide_hook.png",
  "mimeType": "image/png"
}
```

**確認ポイント**:
- ✅ `image_url` フィールドが存在する
- ✅ `image_url` が `https://res.cloudinary.com/` で始まる
- ✅ `imageData` も含まれている（後方互換性）

## 🗂️ Cloudinaryフォルダ構造

アップロードされた画像は以下の構造で保存されます：

```
wf7-slides/
  └── {script_id}/
      ├── hook.png
      ├── intro.png
      ├── point1.png
      ├── point2.png
      ├── point3.png
      ├── summary.png
      └── cta.png
```

例：`script_id = "test-article-001"` の場合
```
wf7-slides/test-article-001/hook.png
wf7-slides/test-article-001/intro.png
...
```

## ⚠️ エラーハンドリング

### Cloudinary認証エラー

**エラーメッセージ**:
```
Cloudinary credentials not configured. Set CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, and CLOUDINARY_API_SECRET environment variables.
```

**対処方法**:
- 環境変数が正しく設定されているか確認
- Railway サービスが再デプロイされているか確認
- 環境変数の値に余分なスペースや改行がないか確認

### Cloudinaryアップロード失敗

**動作**:
- Cloudinaryアップロードが失敗しても、base64形式のレスポンスは返される
- `image_url` フィールドは `null` になる

**ログ出力**:
```
⚠️ Cloudinary upload failed: <error message>
```

**対処方法**:
- Cloudinary API制限に達していないか確認
- ネットワーク接続を確認
- Cloudinaryダッシュボードでアップロード制限やストレージ上限を確認

## 📊 実装詳細

### 変更されたファイル

1. **`requirements.txt`** - Cloudinaryライブラリ追加
   ```
   cloudinary==1.36.0
   ```

2. **`render_server.py`** - Cloudinaryアップロード機能実装
   - **Lines 20-21**: Cloudinaryインポート追加
   - **Lines 25-30**: Cloudinary設定追加
   - **Lines 150-203**: `upload_image_to_cloudinary()` 関数追加
   - **Lines 693-719**: Phase4aレスポンスに`image_url`追加

### 主要関数

**`upload_image_to_cloudinary(img, section, script_id)`**:
- PIL Imageをバイトストリームに変換
- Cloudinaryにアップロード
- `secure_url` を返す（`https://res.cloudinary.com/...`）
- エラー時は例外をスロー

**レスポンス構造**:
```python
{
    "success": True,
    "section": "hook",
    "duration": 5,
    "image_url": "https://res.cloudinary.com/...",  # ✅ NEW
    "imageData": "<base64>",  # Backward compatibility
    "image_size_bytes": 42000,
    "script_id": "test-article-001",
    "filename": "slide_hook.png",
    "mimeType": "image/png"
}
```
