## 📊 3層構造のメリット

### 1. **明確な関心の分離**
- **層1（CLAUDE.md）**: 運用・プロセス
- **層2（workflow-design.mdc）**: 設計・アーキテクチャ
- **層3（n8n-mcp-usage.mdc）**: ツール・コマンド詳細

### 2. **段階的な詳細化**
```
運用ルール（抽象度高）
    ↓
設計ガイド（抽象度中）
    ↓
MCPツール詳細（抽象度低・具体的）
```

### 3. **双方向参照の明示**
- 上位層から下位層へ: 詳細情報へのナビゲーション
- 下位層から上位層へ: コンテキスト確認

### 4. **情報重複の完全排除**
- 各層が固有の責任を持つ
- 同じ情報を複数ファイルに記載しない

### 5. **拡張性**
```
将来追加可能なガイド:
- /railway-deployment.mdc
- /fastapi-optimization.mdc
- /notion-integration.mdc

すべて層1（CLAUDE.md）から参照される
```

## 📝 まとめ

### 3層構造の効果

1. **自動的な統合**: Claude Codeが3つのガイドを自動的に考慮
2. **明確な責任**: 各層が固有の役割を持つ
3. **情報の一元化**: 重複なく必要な情報にアクセス
4. **拡張性**: 新しいガイドを簡単に追加可能
5. **保守性**: 各ガイドを独立して更新可能

**運用フロー**:
```
層1確認 → 層2参照 → 層3実行 → 層1に従って保存
```

**情報配置**:
