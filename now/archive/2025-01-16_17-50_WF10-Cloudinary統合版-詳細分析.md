## 技術的詳細分析

### 1. Google Driveからのダウンロード

**ノード**: HTTP Request - Download Image

```javascript
{
  "method": "GET",
  "url": "https://drive.google.com/uc?export=download&id={{ $json.google_drive_file_id }}",
  "responseFormat": "file"
}
```

**特徴**:
- ✅ Binary dataとしてダウンロード（n8n内部で保持）
- ✅ リダイレクトは許容（n8nが自動的に追跡）
- ⚠️ ファイルサイズ制限: n8nのメモリに依存

**トレードオフ**:
- ✅ 確実にファイルを取得できる
- ❌ n8nサーバーのメモリを消費

---

### 2. Cloudinary署名生成

**ノード**: Code - Generate Cloudinary Signature

```javascript
const crypto = require('crypto');

// 環境変数から取得
const cloudName = $env.CLOUDINARY_CLOUD_NAME;
const apiKey = $env.CLOUDINARY_API_KEY;
const apiSecret = $env.CLOUDINARY_API_SECRET;

// タイムスタンプ生成
const timestamp = Math.floor(Date.now() / 1000);

// 署名文字列
const folder = 'n8n-images';
const stringToSign = `folder=${folder}&timestamp=${timestamp}${apiSecret}`;

// SHA-1ハッシュ生成
const signature = crypto
  .createHash('sha1')
  .update(stringToSign)
  .digest('hex');

return {
  signature,
  timestamp,
  folder,
  cloudName,
  apiKey
};
```

**セキュリティ特性**:
- ✅ API Secretはサーバー側のみで使用（クライアントに露出しない）
- ✅ タイムスタンプベースの署名で再利用攻撃を防止
- ✅ SHA-1ハッシュで改ざん検知

**制限事項**:
- ⚠️ 環境変数が必須（CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET）
- ⚠️ タイムスタンプのズレによる署名エラーの可能性

### 3. Cloudinaryへのアップロード

**ノード**: Code - Upload to Cloudinary

```javascript
// バイナリデータ取得
const binaryData = await this.helpers.getBinaryDataBuffer(0, 'data');
const mimeType = this.getNodeParameter('mimeType', 0, 'image/png');

// Base64エンコード
const base64Data = binaryData.toString('base64');
const dataUri = `data:${mimeType};base64,${base64Data}`;

// Cloudinary API呼び出し
const response = await this.helpers.httpRequest({
  method: 'POST',
  url: `https://api.cloudinary.com/v1_1/${cloudName}/image/upload`,
  headers: {
    'Content-Type': 'application/json'
  },
  body: {
    file: dataUri,
    folder: folder,
    timestamp: timestamp,
    api_key: apiKey,
    signature: signature
  },
  json: true
});

return {
  secure_url: response.secure_url,
  public_id: response.public_id,
  format: response.format,
  width: response.width,
  height: response.height,
  bytes: response.bytes,
  created_at: response.created_at
};
```

**パフォーマンス特性**:
- ⚠️ Binary → Base64変換でサイズ増加（約33%増）
- ⚠️ アップロード時間: ネットワーク速度に依存
- ✅ Cloudinary CDNによる高速配信

**エラーハンドリング**:
- 署名エラー → `401 Unauthorized`
- フォーマットエラー → `400 Bad Request`
- サイズ超過 → `413 Payload Too Large`

### 4. Runway Gen-3 API呼び出し

**ノード**: HTTP Request - Runway Gen-3

```javascript
{
  "method": "POST",
  "url": "https://queue.fal.run/fal-ai/runway-gen3/turbo/image-to-video?fal_webhook=https://n8n-python-production-344b.up.railway.app/webhook/wf10-webhook",
  "authentication": "predefinedCredentialType",
  "nodeCredentialType": "falAiApi",
  "sendBody": true,
  "specifyBody": "json",
  "jsonBody": {
    "image_url": "={{ $('Code - Upload to Cloudinary').first().json.secure_url }}",
    "prompt": "={{ $('Set - Test Data').first().json.台本本文 }}",
    "duration": 10,
    "ratio": "16:9"
  }
}
```

**重要なポイント**:
- ✅ `secure_url`を使用（HTTPS、CDN経由）
- ✅ Cloudinary URLは認証不要（public URL）
- ✅ リダイレクトなし（Cloudinaryの直接URL）
- ✅ MIME typeが明確（Cloudinaryが返す）

**Webhook設定**:
- 非同期処理（fal_webhook指定）
- 完了時にWF10-Webhookを呼び出し

## webContentLinkアプローチとの比較

### アプローチA: webContentLink（テンプレートv7eMABZVv8Un2FSn）

```javascript
// Upload to Google Drive → webContentLink取得
{
  "webContentLink": "https://drive.google.com/uc?export=download&id=FILE_ID&confirm=t"
}

// FAL ltxv-13b API
{
  "image_url": "={{ $json.webContentLink }}",
  "prompt": "..."
}
```

**メリット**:
- ✅ シンプル（ノード数少ない）
- ✅ 外部サービス依存なし（Google Driveのみ）
- ✅ ペイロードサイズ極小（~1KB）
- ✅ アップロード1回のみ

**デメリット**:
- ❌ Runway Gen-3 APIで動作するか未検証
- ❌ `&confirm=t`パラメータの有効期限不明
- ❌ リダイレクトの可能性（Runway Gen-3が拒否）
- ❌ ファイル共有設定に依存

**互換性**:
- ✅ FAL ltxv-13b: 動作確認済み（テンプレート実績）
- ❓ Runway Gen-3: **未検証**（厳格なURL要件）

---

### アプローチB: Cloudinary統合（現行WF10）

```javascript
// Download → Upload to Cloudinary → Runway Gen-3
{
  "image_url": "https://res.cloudinary.com/CLOUD_NAME/image/upload/v1234567890/n8n-images/FILE_NAME.png"
}
```

**メリット**:
- ✅ Runway Gen-3で**動作確認済み**
- ✅ リダイレクトなし（直接URL）
- ✅ CDN配信で高速
- ✅ MIME type明確
- ✅ ファイルサイズ制限なし（Cloudinaryプランに依存）

**デメリット**:
- ❌ 複雑（ノード数多い）
- ❌ 外部サービス依存（Cloudinary）
- ❌ API Secret管理が必要
- ❌ アップロード2回（Google Drive → n8n → Cloudinary）

**コスト**:
- Cloudinary無料プラン: 25GB/月、25GBストレージ
- 超過時: 従量課金

---

**メリット**:
- ✅ Runway Gen-3で動作確認済み
- ✅ 外部サービス依存なし

**デメリット**:

- ❌ n8nのメモリ消費大
- ❌ ネットワーク帯域消費大

**廃止理由**: Cloudinaryに移行したため
