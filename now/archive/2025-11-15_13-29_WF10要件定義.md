### 1.2 詳細技術比較表

#### Runway Gen-3 on fal.ai（選定技術）

**技術仕様**:
```yaml
モデル: fal-ai/runway-gen3/turbo/image-to-video
プロバイダー: fal.ai Queue System
実装方式: Webhook-based非同期アーキテクチャ
```

**✅ 強み:**
- **完全なWebhook対応**: fal.ai Queue System（`queue.fal.run`）で実証済み
- **MCP対応**: am0y/mcp-fal, piebro/fal-ai-mcp-server（複数実装あり）
- **20秒動画生成確認済み**: `duration`パラメータで20秒指定可能（公式対応）
- **解像度**: 1280x768推奨（その他カスタム設定可能）
- **即時利用可能**: Waitlistなし、開発即開始可能
- **信頼性**: fal.ai基盤の安定したQueue System

**⚠️ 懸念事項:**
- **コスト**: $0.05/秒 = $1.00/20秒動画（月100本で$100/月）
- **動画品質**: MVP段階での品質評価必須（Luma AIとの比較）
- **カスタマイズ性**: Promptパラメータの最適化が必要

**Webhookフロー（fal.ai Queue Systemパターン）:**
```
n8n HTTP Request → fal.ai/runway-gen3/turbo/image-to-video
  ↓
queue.fal.run レスポンス（request_id返却）
  ↓ 即座にリターン（非同期）
  ↓
[外部: fal.aiサーバーで動画生成 ~60-120秒]
  ↓
Webhook Trigger (n8n) ← queue.fal.runからWebhook POST
  ↓
Payload解析 (video.url, status, generation_id)
  ↓
If (status === "completed")
  ↓
処理継続（動画ダウンロード、Notion保存、SNS出力準備等）
```

**MCP統合パターン（fal.ai MCPサーバー使用）:**
```yaml
MCPサーバー選択肢:
  - am0y/mcp-fal: fal.ai全般対応、画像・動画生成ツール提供
  - piebro/fal-ai-mcp-server: fal.ai専用、Queue System統合

統合方法:
  1. Claude Desktop設定ファイルでMCPサーバー登録
  2. n8n開発時にMCPツールでAPIパラメータ設計支援
  3. n8n HTTP Requestノードで queue.fal.run 直接呼び出し
  4. MCPサーバーは開発時の設定支援・デバッグ・検証用途
```

**技術的利点**:
- **WF7失敗回避**: Wait+Loopパターン不使用、完全非同期
- **スケーラビリティ**: fal.ai Queue Systemで並列生成対応

## 📐 2. Phase 0検証計画

### 2.1 データサイズ見積もり

#### 入力データ
- **台本テキスト**: Notion Hub（台本1本あたり ~2KB）
- **画像素材**: Notion添付またはURL参照（~500KB/枚, 最大3枚想定）
- **合計入力**: ~2MB/動画1本

#### 出力データ
- **動画ファイル**: 20秒, 720p想定
  - 計算: 720p × 20s × ビットレート ~5Mbps = ~12.5MB/本
- **3形式出力**: 12.5MB × 3 = 37.5MB/台本1本
- **バッチ処理想定**: 10本/日 → 375MB/日

#### リスクレベル評価
- **入力サイズ**: LOW (<10MB)
- **出力サイズ**: MEDIUM (10-50MB/本)
- **バイナリデータ**: HIGH (動画ファイル)

### 2.2 アーキテクチャ決定

**選定アーキテクチャ**: **Webhook + Sub-workflow Pattern**

#### 理由
1. **バイナリデータ**: 動画ファイル >10MB → Sub-workflow推奨
2. **非同期処理**: Webhook Triggerで非同期イベント受信
3. **形式変換分離**: 3形式変換をSub-workflowで並列処理可能

#### 構成案
```
[Main Workflow]
  ├─ Notion Trigger (台本データ取得)
  ├─ Runway Gen-3 動画生成開始 (HTTP Request to fal.ai)
  │   └─ queue.fal.run/fal-ai/runway-gen3/turbo/image-to-video
  └─ 即座に完了（非同期）

[Webhook Sub-workflow]
  ├─ Webhook Trigger (fal.ai Queue System完了通知受信)
  ├─ Payload解析 (video.url, status, generation_id)
  ├─ 動画ダウンロード (HTTP Request)
  ├─ Execute Workflow: Format Converter (3形式並列)
  │   ├─ Sub-workflow 1: 9:16 Vertical
  │   ├─ Sub-workflow 2: 1:1 Square
  │   └─ Sub-workflow 3: 16:9 Horizontal
  └─ Notion更新 (動画URL保存)
```

## 🏗️ 3. ワークフロー構成設計

### 3.1 全体構成図

```
┌─────────────────────────────────────────┐
│ WF10-Main: 動画生成起動                    │
│ Trigger: Notion Database (台本DB監視)      │
│ ├─ Notion: 台本データ取得                  │
│ ├─ Runway Gen-3: 動画生成開始              │
│ │   └─ queue.fal.run (HTTP Request)      │
│ └─ 即座に完了（非同期）                     │
└─────────────────────────────────────────┘
                    ↓ (webhook設定)
┌─────────────────────────────────────────┐
│ WF10-Webhook: 動画処理                    │
│ Trigger: Webhook (fal.ai完了通知)          │
│ ├─ Payload解析 (video.url, status)       │
│ ├─ If: status = "completed"?             │
│ ├─ HTTP Request: 動画ダウンロード           │
│ ├─ Execute Workflow: WF10-Format-9-16    │
│ ├─ Execute Workflow: WF10-Format-1-1     │
│ ├─ Execute Workflow: WF10-Format-16-9    │
│ └─ Notion: 動画URL更新                     │
└─────────────────────────────────────────┘
                    ↓ (形式変換Sub-workflow)
┌─────────────────────────────────────────┐
│ WF10-Format-9-16: Vertical変換            │
│ ├─ Binary Data受信                        │
│ ├─ [形式変換処理 - Phase 1で詳細設計]      │
│ └─ Output: 9:16 動画                      │
└─────────────────────────────────────────┘
（WF10-Format-1-1、WF10-Format-16-9も同様）
```

### 3.2 主要ノード設計

#### WF10-Main Workflow

**1. Notion Database Trigger**
- **機能**: 台本DBの新規レコード検出
- **設定**:
  - Database ID: [Notion Hub 台本DB]
  - Trigger on: New records
  - Poll interval: 1分

**2. Notion - Get Database Item**
- **機能**: 台本詳細取得
- **取得項目**:
  - タイトル (title)
  - 台本本文 (rich_text)
  - 対象SNS (multi_select)
  - 画像素材URL (files)

**3. HTTP Request - Runway Gen-3 動画生成開始**
- **機能**: fal.ai Queue System経由でRunway Gen-3 API呼び出し（非同期）
- **設定**:
  - Method: POST
  - URL: `https://queue.fal.run/fal-ai/runway-gen3/turbo/image-to-video`
  - Authentication: Bearer Token (fal.ai API Key)
  - Headers:
    - `Content-Type: application/json`
    - `Authorization: Key {{ $env.FAL_API_KEY }}`
  - Body (JSON):
    ```json
    {
      "prompt_image": "{{ $json.画像素材URL[0] }}",
      "prompt_text": "{{ $json.台本本文 }}",
      "duration": 20,
      "ratio": "16:9",
      "webhook_url": "{{ $workflow.webhook_url }}"
    }
    ```
- **レスポンス**: `{ "request_id": "req_xxx", "status": "IN_QUEUE" }`

#### WF10-Webhook Sub-workflow

**1. Webhook Trigger**
- **機能**: fal.ai Queue System完了通知受信
- **設定**:
  - Path: `/wf10-runway-webhook`
  - Method: POST
  - Authentication: Webhook Secret (環境変数)
  - Response Mode: `lastNode` (即座にHTTP 200返却)

**2. Set - Payload解析**
- **機能**: fal.ai Webhook payload解析
- **抽出項目**:
  - video.url (完成動画URL)
  - status (completed/failed/in_progress)
  - request_id (リクエストID)
  - duration (動画長: 20秒確認用)
  - error (エラーメッセージ、失敗時)

**3. If - Status Check**
- **機能**: 完了ステータス確認
- **条件**: `{{ $json.status }} === "completed"`
- **true分岐**: 動画処理継続
- **false分岐**: エラーログ + Notion更新（失敗記録）

**4. HTTP Request - 動画ダウンロード**
- **機能**: 完成動画取得
- **設定**:
  - Method: GET
  - URL: `{{ $json.video.url }}`
  - Response Format: File
  - Binary Property: `video_data`
  - File Name: `runway_{{ $json.request_id }}_original.mp4`

**5. Execute Workflow × 3**
- **機能**: 形式変換Sub-workflow呼び出し（並列実行）
- **呼び出し先**:
  - WF10-Format-9-16 (Vertical)
  - WF10-Format-1-1 (Square)
  - WF10-Format-16-9 (Horizontal)
- **入力**: Binary Data (`video_data`)
- **出力**: 変換後動画URL

**6. Notion - Update Database Item**
- **機能**: 台本DBレコード更新
- **更新項目**:
  - 動画ステータス: "完成"
  - Vertical動画URL: `{{ $node["Execute WF10-Format-9-16"].json.video_url }}`
  - Square動画URL: `{{ $node["Execute WF10-Format-1-1"].json.video_url }}`
  - Horizontal動画URL: `{{ $node["Execute WF10-Format-16-9"].json.video_url }}`
  - 完成日時: `{{ $now }}`

### 3.3 エラーハンドリング設計

#### 動画生成失敗
- **検出**: Webhook payload `status === "failed"`
- **対応**:
  1. Notion更新（ステータス: "生成失敗"）
  2. エラーログ記録（generation_id, error_message）
  3. 管理者通知（Slack/メール - Phase 2で実装）

#### Webhook未到達
- **検出**: WF10-Main実行後5分経過でWebhook未受信
- **対応**:
  1. fal.ai Queue API: Status Check (HTTP Request GET)
     - URL: `https://queue.fal.run/fal-ai/runway-gen3/turbo/image-to-video/requests/{{ request_id }}/status`
  2. ステータス確認: "completed" → 手動Webhook Trigger
  3. ステータス確認: "failed" → エラー処理
  4. ステータス確認: "IN_QUEUE" / "IN_PROGRESS" → 再度待機（最大5分）

#### 形式変換失敗
- **検出**: Execute Workflow エラー
- **対応**:
  1. 元動画URLをNotionに保存（手動変換可能に）
  2. エラーログ記録（変換タイプ、エラー詳細）
  3. 他の形式変換は継続（部分的成功を許容）
