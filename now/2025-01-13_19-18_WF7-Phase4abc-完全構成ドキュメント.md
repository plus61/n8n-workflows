## ⚠️ 重要な注意事項

### 1. Execute Workflowノードの設定（絶対に変更しない）

**Phase4aのExecute Workflowノード**:
- **workflowId**: `hfhZijyKIt1DjI1V` （Phase4b FIXED）
- **絶対に `mfRdJJFJRKmeBjKv` （Phase4c）に変更しないこと**

**理由**:
- Phase4cはWebhook triggerを持つため、Execute Workflowノードから呼べない
- Phase4bはExecute Workflow Triggerを持つため、正しく呼べる
- 誤ったIDに変更すると "Missing node to start execution" エラーが発生

### 2. トリガータイプの違い

| ワークフロー | トリガータイプ | 呼び出し方法 | 実行モード |
|------------|--------------|------------|-----------|
| Phase4a | Webhook | curl/HTTP POST | webhook |
| Phase4b FIXED | Execute Workflow Trigger | Execute Workflowノード | integrated |
| Phase4c | Webhook | curl/HTTP POST | webhook |

**Execute Workflow Triggerを持つワークフローのみが、Execute Workflowノードから呼び出せる。**

### 3. データフロー順序

**正しい順序**:
1. Phase4a Webhook呼び出し（script_id）
2. Phase4aがPhase4bを7回呼び出し（Execute Workflowノード）
3. Phase4bが7本の動画URL生成
4. Phase4cをWebhook呼び出し（7 video URLs）※ 別途手動/自動
5. Phase4cが1本の結合動画生成

**Phase4aとPhase4cは直接接続されていない**（現状の設計）

### 4. Duration変換の重要性

**Phase4b FIXED**: FAL API composeエンドポイントはミリ秒を要求
- Phase4aから受け取る `duration`: 秒単位（3, 10, 13, ...）
- FAL APIに送る `duration`: ミリ秒単位（3000, 10000, 13000, ...）
- **必ず `duration * 1000` で変換**
