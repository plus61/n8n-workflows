## 📊 アーキテクチャ概要

### 2ノード構成（MCPベストプラクティス）

```
Create Video Task (kie.ai API呼び出し)
         ↓
[Save Video Request] ← Google Sheets Append操作
         ↓           （task_id, prompt, image_url等を即時記録）
Poll Video Status (動画完成待機)
         ↓
[Update Video Record] ← Google Sheets Update操作
         ↓              （video_url, completion_time等を更新）
（次のノード）
```

### なぜ2ノード構成か？

**MCPテンプレート分析結果**:
- 214,907 viewsテンプレートは **append → update** パターンを採用
- **理由1**: 処理途中でエラーが発生しても初期記録は保持される
- **理由2**: `matchingColumns`でレコード特定し、部分更新が可能
- **理由3**: 時系列追跡（request_time → completion_time）で処理時間測定可能

## 🔧 実装手順

### Step 1: Google Sheetsスプレッドシート作成

1. **新規スプレッドシート作成**:
   - Google Sheetsを開く: https://docs.google.com/spreadsheets/
   - "空白" をクリック
   - スプレッドシート名: `WF10_Video_Production_Log`

2. **シート名変更**:
   - デフォルト「シート1」を右クリック
   - 「名前を変更」→ `Video_Production_Log`

3. **ヘッダー行設定（A1:J1）**:
   ```
   task_id | request_time | prompt | image_url | status | aspect_ratio | model | video_url | completion_time | duration_seconds
   ```

4. **Spreadsheet ID取得**:
   - URL例: `https://docs.google.com/spreadsheets/d/1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgvE2upms/edit`
   - Spreadsheet ID: `/d/` の後の文字列 → `1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgvE2upms`
   - この IDをコピー（後で使用）

### Step 2: n8n Google Sheets認証設定

1. **n8n UIにアクセス**:
   - https://n8n-python-production-344b.up.railway.app/

2. **Credential作成**:
   - 画面右上 **Credentials** → **Add Credential**
   - **Google Sheets OAuth2 API** を選択
   - **Authorize** ボタンクリック → Googleアカウントでログイン
   - 権限承認: `https://www.googleapis.com/auth/spreadsheets`
   - Credential名: `Google Sheets account` (デフォルトでOK)
   - **Save** クリック

3. **Credential ID取得**:
   - 保存後、URLに表示される credential ID をコピー
   - 例: `https://.../credentials/123` → ID は `123`

### Step 3: WF10ワークフローにノード追加

#### 3-1. Save Video Request ノード追加

1. **Create Video Task ノードの直後に挿入**:
   - Create Video Task ノードをクリック
   - 右側の **+** ボタン
   - 検索: `Google Sheets`
   - **Google Sheets** ノードを追加

2. **ノード名変更**:
   - ノードヘッダーをダブルクリック
   - 名前: `Save Video Request`

3. **パラメータ設定**:
   ```json
   Resource: Sheet
   Operation: Append Row

   Document:
     Mode: ID
     Value: [Step 1で取得したSpreadsheet ID]

   Sheet:
     Mode: ID
     Value: Video_Production_Log

   Columns:
     Mapping Mode: Define Below
     Columns:
       task_id: ={{ $json.taskId }}
       request_time: ={{ $now.toISO() }}
       prompt: ={{ $('Upload to Google Drive').item.json.prompt }}
       image_url: ={{ $('Create Direct Link').item.json.directLink }}
       status: processing
       aspect_ratio: 9:16
       model: veo-3.1
       video_url:
       completion_time:
       duration_seconds:
   ```

4. **Credential設定**:
   - **Credential to connect with**: [Step 2で作成したCredential]

5. **エラー処理設定**:
   - ノード右上 **...** → **Settings**
   - **Continue On Fail**: ON に変更
   - 理由: Sheets記録失敗でもワークフロー継続

#### 3-2. Update Video Record ノード追加

1. **Poll Video Status ノードの直後に挿入**:
   - Poll Video Status ノードをクリック
   - 右側の **+** ボタン
   - 検索: `Google Sheets`
   - **Google Sheets** ノードを追加

2. **ノード名変更**:
   - 名前: `Update Video Record`

3. **パラメータ設定**:
   ```json
   Resource: Sheet
   Operation: Update Row

   Document:
     Mode: ID
     Value: [Save Video Requestと同じSpreadsheet ID]

   Sheet:
     Mode: ID
     Value: Video_Production_Log

   Columns:
     Mapping Mode: Define Below
     Matching Columns: task_id  ← 重要！
     Columns:
       task_id: ={{ $('Save Video Request').first().json.task_id }}
       status: completed
       video_url: ={{ $json.videoUrl }}
       completion_time: ={{ $now.toISO() }}
       duration_seconds: ={{ Math.floor($now.diff($('Save Video Request').first().json.request_time, 'seconds')) }}
   ```

4. **Credential設定**:
   - **Credential to connect with**: [Save Video Requestと同じCredential]

5. **エラー処理設定**:
   - **Continue On Fail**: ON に変更（推奨）

### Step 4: ワークフロー保存とテスト

1. **ワークフロー保存**:
   - 画面右上 **Save** ボタンクリック

2. **Save Video Request 単体テスト**:
   - Create Video Task ノードを実行（Execute Node）
   - Save Video Request ノードを実行
   - Google Sheetsを開く → 新規行が追加されているか確認
   - 確認項目: task_id, request_time, prompt, image_url, status=processing

3. **Update Video Record 単体テスト**:
   - Poll Video Status ノードを実行（既存のtaskIdで）
   - Update Video Record ノードを実行
   - Google Sheetsを確認 → 該当行が更新されているか確認
   - 確認項目: status=completed, video_url, completion_time, duration_seconds

4. **E2Eテスト**:
   - Webhookからワークフロー全体を実行
   - Google Sheetsで完全なレコード追跡を確認

## ⚠️ トラブルシューティング

### エラー1: "Document not found"
**原因**: Spreadsheet IDが間違っている
**解決**: Step 1でコピーしたIDを再確認、documentId.valueに正しく設定

### エラー2: "Sheet 'Video_Production_Log' not found"
**原因**: シート名が間違っている
**解決**: Google Sheetsでシート名を確認、sheetName.valueと一致させる

### エラー3: "No matching rows found" (Update Video Record)
**原因**: Save Video Requestが実行されていない、またはtask_idが一致しない
**解決**:
1. Save Video Requestの実行ログを確認
2. Google Sheetsで該当task_idのレコードが存在するか確認
3. Update Video Recordの `matchingColumns` が `["task_id"]` になっているか確認

### エラー4: "Invalid credentials"
**原因**: Google Sheets認証が失敗している
**解決**:
1. n8n Credentials画面で該当Credentialを削除
2. Step 2を再実行し、新規Credentialを作成
3. 両ノードのCredential設定を更新

### エラー5: "Expression error: $('Save Video Request').first() is undefined"
**原因**: Update Video RecordノードでSave Video Requestノードが参照できない
**解決**:
1. ノード名が完全一致しているか確認（大文字小文字含む）
2. Save Video Requestノードが実行済みか確認
3. ワークフロー実行順序を確認（Save → Create → Poll → Update）

## 📊 MCPテンプレート学習ポイント

### パターン1: 2段階記録（append → update）
```javascript
// ❌ 悪い例：1ノードでappendOrUpdate
{
  "operation": "appendOrUpdate",
  "matchingColumns": ["task_id"],
  "value": {
    "task_id": "={{ $json.taskId }}",
    "status": "={{ $json.status }}",
    "video_url": "={{ $json.videoUrl }}"  // ← 初期記録時はundefined
  }
}

// ✅ 良い例：2ノード分離
// ノード1: Append（初期記録）
{
  "operation": "append",
  "value": {
    "task_id": "={{ $json.taskId }}",
    "status": "processing",
    "video_url": ""  // ← 空欄で記録
  }
}

// ノード2: Update（完了時更新）
{
  "operation": "update",
  "matchingColumns": ["task_id"],
  "value": {
    "task_id": "={{ $('Save Video Request').first().json.task_id }}",
    "status": "completed",
    "video_url": "={{ $json.videoUrl }}"  // ← ここで初めて記録
  }
}
```

**理由**:
- 処理途中でエラーが発生しても初期記録は保持される
- updateノードが失敗しても、task_idで手動補完可能
- 時系列追跡（いつリクエストし、いつ完成したか）が明確

### パターン2: matchingColumns の使い方
```javascript
// ✅ 正しい使用法
{
  "operation": "update",
  "matchingColumns": ["task_id"],  // ← 既存レコードを特定するカラム
  "value": {
    "task_id": "={{ $('Save Video Request').first().json.task_id }}",
    "status": "completed",
    "video_url": "={{ $json.videoUrl }}"
  }
}
```

**重要**: `matchingColumns`に指定したカラムは、valueにも必ず含める必要がある

### パターン3: クロスノード参照
```javascript
// ❌ 間違い：現在ノードのデータを参照
{
  "task_id": "={{ $json.task_id }}"  // ← Update Video Recordノードには存在しない
}

// ✅ 正しい：前のノードのデータを参照
{
  "task_id": "={{ $('Save Video Request').first().json.task_id }}"
}
```

**構文**: `$('ノード名').first().json.フィールド名`

### パターン4: タイムスタンプと時間計算
```javascript
// タイムスタンプ記録
"request_time": "={{ $now.toISO() }}"  // ISO 8601形式

// 経過時間計算
"duration_seconds": "={{ Math.floor($now.diff($('Save Video Request').first().json.request_time, 'seconds')) }}"
```
