**重要度**: ⭐⭐⭐⭐⭐
**WF-Bへの適用**: スキーマバリデーションパターン

#### アーキテクチャ
```
AI Agent → Schema Check (Code Node) → Switch Node
  ├─ Invalid → Retry with updated prompt (max 4回)
  └─ Valid → Continue to output
```

#### キーポイント
- **Structured Output Parserを使わない**手動バリデーション
- `runIndex`カウンターでリトライ制御（最大4回）
- バリデーションエラーをプロンプトに組み込んでリトライ
- より柔軟なエラーハンドリングが可能

#### WF-Bへの応用
```javascript
// Function Node: Validate JSON Schema
const json = $input.first().json;
const errors = [];

// Enum validation
if (!['improve', 'pause', 'scale'].includes(json.next_decision)) {
  errors.push('Invalid next_decision');
}

// Length validation
if (json.next_action?.length > 200) {
  errors.push('next_action exceeds max length');
}

// Array validation
if (!Array.isArray(json.insights) ||
    json.insights.length < 2 || json.insights.length > 4) {
  errors.push('insights must have 2-4 items');
}

return {
  json: {
    valid: errors.length === 0,
    errors: errors,
    data: json,
    runIndex: $runIndex
  }
};
```

### 🏅 Template #7: Robust JSON Parser for AI Outputs (ID: 5146)
**重要度**: ⭐⭐⭐
**WF-Bへの適用**: エラーハンドリングパターン

#### アーキテクチャ
```
AI Output → Pre-processing (escape control chars)
  → JSON Parse → Validation → Post-processing
```

#### キーポイント
- **Dirty JSON対応**: 制御文字のエスケープ、trailing commaの削除
- **戦略的抽出**: 大きなテキストから```json```ブロックを抽出
- **フォールバック**: パース失敗時の代替処理

#### WF-Bへの応用
```javascript
// Code Node: Clean and Parse JSON
let rawOutput = $input.first().json.output;

// Remove markdown code blocks
rawOutput = rawOutput.replace(/```json\s*/g, '').replace(/```\s*/g, '');

// Escape control characters
rawOutput = rawOutput.replace(/[\n\r\t]/g, (char) => {
  return char === '\n' ? '\\n' : char === '\r' ? '\\r' : '\\t';
});

// Remove trailing commas
rawOutput = rawOutput.replace(/,(\s*[}\]])/g, '$1');

try {
  const parsed = JSON.parse(rawOutput);
  return { json: { success: true, data: parsed } };
} catch (error) {
  return {
    json: {
      success: false,
      error: error.message,
      raw: rawOutput
    }
  };
}
```

## 3. 実装パターン分類

### A. AI Agent + Google Sheets統合

#### Pattern A1: Direct Append (Templates #2, #3, #15)
```
AI Agent → Transform → Google Sheets Append
```
- **利点**: シンプル、高速
- **欠点**: 重複チェックなし
- **WF-Bでの適用**: 初回実装で使用

#### Pattern A2: Lookup + Conditional Append (Template #2)
```
AI Agent → Transform → Check Existing →
  IF not exists → Append
```
- **利点**: 重複防止、データ整合性
- **欠点**: 複雑化、2回のシート操作
- **WF-Bでの適用**: 将来的な改善で検討

#### Pattern A3: Agent with Self-Modifying Rules (Template #1)
```
AI Agent → Read/Write Rules (Google Sheets) → Execute with Rules
```
- **利点**: 動的ルール変更、学習可能
- **欠点**: 高度な設定が必要
- **WF-Bでの適用**: 現時点では不要

---

### B. Structured Output Parser vs Manual Validation

#### Pattern B1: Structured Output Parser (Templates #8, #9, #10)
```yaml
# Output Parser設定
schema:
  type: object
  properties:
    next_decision:
      type: string
      enum: ["improve", "pause", "scale"]
  required: ["next_decision"]
  additionalProperties: false
```
- **利点**: 自動バリデーション、エラーメッセージ自動生成
- **欠点**: 柔軟性に欠ける、複雑なスキーマで問題
- **WF-Bでの推奨**: Q4で採用

#### Pattern B2: Manual Validation Loop (Template #6)
```
AI Agent → Code Validation → Switch
  ├─ Invalid → Update Prompt → Retry
  └─ Valid → Continue
```
- **利点**: 柔軟なエラーハンドリング、カスタム検証ロジック
- **欠点**: 実装が複雑、保守コスト高
- **WF-Bでの推奨**: Phase 0検証後、必要に応じて追加

#### Pattern B3: Hybrid (Auto-fixing + Structured)
```
AI Agent → Auto-fixing Parser → Structured Output Parser
```
- **利点**: 高い成功率、厳密な検証
- **欠点**: 処理時間増加
- **WF-Bでの推奨**: 本番環境で成功率低下時に検討

---

### C. Split In Batches処理

#### Pattern C1: Basic Sequential (Template #13)
```
Input → Split In Batches (size: 10) → Process → Merge
```
- **利点**: メモリ効率、タイムアウト防止
- **欠点**: 処理時間増加
- **WF-Bでの適用**: 単一行処理のため不要

#### Pattern C2: Rate Limit Management (Template #14)
```
Split In Batches → Process → Wait (5sec) → Next Batch
```
- **利点**: API制限回避
- **欠点**: 全体処理時間増加
- **WF-Bでの適用**: OpenAI APIレート制限対応に将来検討

---

### D. エラーハンドリング戦略

#### Strategy D1: Automatic Retry (Template #13)
```
Error Trigger → Check Failed Executions → Auto Retry
```
- **利点**: 自動復旧、運用負荷軽減
- **欠点**: 無限ループリスク
- **WF-Bでの適用**: Phase 2で実装予定

#### Strategy D2: Validation + Fallback (Template #6, #7)
```
Process → Validate →
  IF invalid → Fallback Logic
  ELSE → Continue
```
- **利点**: データ整合性保証、エラー追跡
- **欠点**: 複雑化
- **WF-Bでの適用**: Q4バリデーションノードで実装

### B. Validation Function (from #6)
```javascript
// Code Node: Validate AI Output
const json = $input.first().json;
const errors = [];
const warnings = [];

// Required fields check
const required = ['next_decision', 'next_action', 'next_segment',
                  'next_keyword_idea', 'insights', 'reasoning'];
for (const field of required) {
  if (!json[field]) {
    errors.push(`Missing required field: ${field}`);
  }
}

// Enum validation
if (json.next_decision &&
    !['improve', 'pause', 'scale'].includes(json.next_decision)) {
  errors.push(`Invalid next_decision: ${json.next_decision}`);
}

if (json.next_segment &&
    !['Cold', 'Middle', 'Hot', 'Current'].includes(json.next_segment)) {
  errors.push(`Invalid next_segment: ${json.next_segment}`);
}

// Length validation
if (json.next_action?.length > 200) {
  errors.push(`next_action exceeds 200 chars: ${json.next_action.length}`);
}

if (json.next_keyword_idea?.length > 100) {
  warnings.push(`next_keyword_idea long: ${json.next_keyword_idea.length}`);
}

if (json.reasoning?.length > 500) {
  warnings.push(`reasoning long: ${json.reasoning.length}`);
}

// Array validation
if (!Array.isArray(json.insights)) {
  errors.push(`insights must be array`);
} else if (json.insights.length < 2 || json.insights.length > 4) {
  errors.push(`insights must have 2-4 items: ${json.insights.length}`);
}

// Additional properties check
const allowedKeys = [...required];
const extraKeys = Object.keys(json).filter(k => !allowedKeys.includes(k));
if (extraKeys.length > 0) {
  warnings.push(`Extra keys found: ${extraKeys.join(', ')}`);
}

return {
  json: {
    valid: errors.length === 0,
    errors: errors,
    warnings: warnings,
    data: json,
    runIndex: $runIndex
  }
};
```
