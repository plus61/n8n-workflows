# now フォルダ運用ルール

**更新日時**: 2025-11-13 08:26:48 JST

## 目的
作業中の最新ファイルに素早くアクセスするための一時作業スペース

---

## 🔴 必須ルール

### 1. すべての新規ファイルは `now/` 配下に配置
**MANDATORY**: コード以外のすべての新規作成ファイルは `now/` ディレクトリに保存すること

### 2. ファイル作成時は必ず日時を取得・記録
**MANDATORY**: ドキュメントやデータファイルを作成する際は、必ず以下を実行：
```bash
date +"%Y-%m-%d %H:%M:%S %Z"
```
取得した日時をファイルのヘッダーまたはメタデータに記録すること

---

## 使用方法

### 作業開始時
1. **日時取得**（必須）
   ```bash
   date +"%Y-%m-%d %H:%M:%S %Z"
   ```

2. **ファイル作成**
   - `now/` ディレクトリ配下に作成
   - ファイル命名規則：`YYYY-MM-DD_HH-MM_説明.拡張子`
   - 例：`2025-01-13_08-26_wf7-phase4c-test.json`
   - 例：`2025-01-13_08-26_実装計画.md`

3. **日時記録**
   - Markdown: ヘッダーに `**作成日時**: 2025-01-13 08:26:48 JST`
   - JSON: `"created_at": "2025-01-13 08:26:48 JST"`

### 作業終了時
`organize-now.sh` スクリプトを実行して整理：
```bash
./organize-now.sh
```

## 自動振り分けルール

### ワークフローファイル (.json)
- **ターゲット**: `workflows/`
- **条件**: n8nワークフロー構造を持つJSONファイル
- **命名**: `wf{番号}_{説明}.json`

### ドキュメント (.md)
以下のキーワードで自動分類：

1. **設計書** → `docs/design/`
   - キーワード: 設計, デザイン, 仕様, アーキテクチャ

2. **実装計画** → `docs/implementation/`
   - キーワード: 実装, 手順, 計画, Todo

3. **テスト結果** → `docs/testing/`
   - キーワード: テスト, 検証, 結果, 実行

4. **検証レポート** → `docs/verification/`
   - キーワード: 検証, チェックリスト, 確認

5. **技術知識** → `docs/knowledge/`
   - キーワード: 知識, ナレッジ, ベストプラクティス, Tips

6. **その他** → `docs/`
   - 上記に該当しないドキュメント

### スクリプト (.sh, .py)
- **テストスクリプト** → プロジェクトルート
  - 命名パターン: `test-*.sh`, `test-*.py`
- **その他** → `scripts/`

### データファイル (.json - ワークフロー以外)
- **ターゲット**: `data/`
- **条件**: pindata, payload等のテストデータ

## 🎯 状態管理システム（NEW）

### 概要
経過系列の混乱を防ぐため、`now/` 配下に2つの特別なファイルを常駐させます：

1. **`CURRENT_STATE.md`** - プロジェクトの現在状態（真実の源）
2. **`DECISIONS.md`** - 重要な技術的決定の記録

### 運用ルール
- ✅ **セッション開始時**: 必ず `CURRENT_STATE.md` を確認
- ✅ **重要な決定時**: `DECISIONS.md` に記録
- ✅ **作業完了時**: Claude Codeが自動的に `CURRENT_STATE.md` を更新提案
- ✅ **整理時**: これら2ファイルは `now/` に残る（移動しない）

### CURRENT_STATE.md の使い方
- **目的**: 現在のプロジェクト状態を一元管理
- **内容**: 使用すべきファイル、避けるべきファイル、次のアクション
- **更新頻度**: 重要な作業完了時（Claude Codeが自動提案）

### DECISIONS.md の使い方
- **目的**: 重要な技術的決定を記録し、なぜその選択をしたかを明確化
- **記録すべき決定**:
  - ✅ アーキテクチャ選択（例：10ノード版 vs 26ノード版）
  - ✅ API選択（例：FAL API vs Creatomate）
  - ✅ アプローチ選択（例：再作成 vs 修正）
- **記録不要**:
  - ❌ 些細なバグ修正
  - ❌ コードの微調整

### 状態管理ファイルの整理
`organize-now.sh` 実行時、以下のファイルは **移動せず `now/` に残ります**：
- `CURRENT_STATE.md`
- `DECISIONS.md`
- `README.md`

---

## 注意事項
- ✅ `now/` フォルダは一時作業スペースなので、必ず定期的に整理すること
- ✅ 重要なファイルは整理前にバックアップを推奨
- ✅ 整理スクリプトは確認プロンプト付きで安全に実行可能
- ✅ 日時取得を忘れた場合は即座に追記すること
- ✅ すべての新規ファイルは必ず `now/` 配下に作成すること
- ✅ **セッション開始時は必ず `CURRENT_STATE.md` を確認すること（NEW）**
