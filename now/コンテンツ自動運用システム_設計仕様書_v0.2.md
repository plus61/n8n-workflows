## 1. システム概要（再掲）
- DMMmodel（Belief構造＋DRM＋プロジェクト思想）を固定コアとし、note記事・SNS用コンテンツの自動生成〜改善サイクルを回す。
- キーワード／トレンドは外部データから自動取得し、AI（OpenAI）＋n8nで生成と改善提案を行い、人間はSlackで最終承認のみ実施。

## 2. DMMmodel / .mdc 仕様
### 2-1. 保存場所
- Cursor: `.cursor/rules/{project}.mdc`
- n8n: `Project Config A/B`ノードの`mdc_content`（文字列）

### 2-2. 役割
- 思想／ターゲット／商品設計／トーン／セグメント方針を固定する最上位ルール。全生成物はこの.mdcを必ず参照。

### 2-3. スキーマ（サンプル）
```jsonc
{
  "version": "0.1.0",          // セマンティックバージョン
  "updated_at": "2025-11-17T00:00:00Z",
  "project": "塾向け集客",
  "most_important_rules": ["〜"],
  "target": "学習塾・小規模塾経営者",
  "burning_needs": ["問い合わせ増", "LTV向上"],
  "ideal_future": "〜",
  "concept": "〜",
  "drm_funnel": {
    "front": ["〜"],
    "middle": ["〜"],
    "back": ["〜"]
  },
  "usp": ["〜"],
  "tone": "敬意を払いながら率直に。専門性と実務感を出す",
  "content_guidelines": ["タイトルは40字以内", "ベネフィット先行"],
  "segment_policies": {
    "Cold": "課題顕在化前。教育・気づき重視",
    "Middle": "比較検討中。差別化と社会的証明",
    "Hot": "購入直前。オファー明確化",
    "Current": "既存顧客。アップセル/リテンション"
  }
}
```
- 必須キー: `version`, `updated_at`, `project`, `most_important_rules`, `target`, `drm_funnel`, `tone`, `segment_policies`。
- n8nでの参照: Functionノードで `const mdc = JSON.parse($json.mdc_content);` としてフィールドを取得。

### 2-4. バージョン管理
- .mdcはGit管理。更新時は`version`/`updated_at`を更新し、コミットメッセージに`mdc:`プレフィックス。

## 3. Editorial Google Sheets 仕様
### 3-1. シート
- シート名: `editorial`（固定）
- ヘッダ順（左→右）: 
  1) `status` (string, enum: idea/draft-generated/published) 
  2) `trending_keyword` (string)
  3) `abstract` (string)
  4) `segment` (string, enum: Cold/Middle/Hot/Current)
  5) `generated_title` (string)
  6) `generated_body` (string)
  7) `note_url` (string, URL or empty)
  8) `note_title` (string)
  9) `note_pv` (number)
 10) `note_likes` (number)
 11) `note_conversion` (number; CV件数または率を明示する列コメント推奨)
 12) `next_decision` (string)
 13) `next_action` (string)
 14) `next_segment` (string, enum or empty)
 15) `next_keyword_idea` (string)
- 型: 数値列は数値。日付列なし（必要なら別途追加）。
- 権限: サービスアカウントメールをシート共有（編集権限）。

### 3-2. 状態遷移
- `idea` → (WF-A生成) → `draft-generated` → (人承認+公開) → `published`。
- WF-Bは`published`のみ処理。再投入時は`next_segment`/`next_keyword_idea`をWF-Aの入力として新規行を追加（status=idea）。

## 4. n8n WF-A: Generate Note Drafts
### 4-1. 目的
- `status=idea`行からnote記事ドラフトをAI生成し、Sheetsに保存、Slackで承認へ回す。

### 4-2. ノード構成
1. Manual Trigger
2. Google Sheets - Get Ideas (`editorial`, 全行取得)
3. Function - Filter Ideas: `items.filter(r => r.json.status === 'idea')`
4. Project Config A: 返却に`mdc_content`(string)と`openai_api_key`を含む
5. Merge Ideas + Config: アイデア行とmdcを1件ずつマージ
6. OpenAI - Generate Note Draft
   - モデル: `gpt-4o-mini`（コスト優先）。長文時は`gpt-4o`に切替可能。
   - 温度: 0.7 / top_p: 1 / max_tokens: 1200
   - プロンプト: .mdc要約 + `trending_keyword` + `abstract` + `segment`を与え、下記JSONスキーマで出力要求
   - 期待JSON:
```json
{
  "generated_title": "string",          
  "generated_body": "markdown string",  
  "segment": "Cold|Middle|Hot|Current", 
  "keyword_used": "string",             
  "reasoning": "string"
}
```
7. Function - Parse OpenAI JSON: `JSON.parse($json.data[0].text)` 相当でsafe-parseし、スキーマ必須キー検証
8. Google Sheets - Update Draft Row: 対応行に`generated_title/body/segment`を上書きし、`status`を`draft-generated`に更新
9. Slack Notify - New Draft: 承認待ち通知を送付

### 4-3. エラー/リトライ
- OpenAI/Sheets/Slack失敗時は`Retry on Fail`有効（最大3回、指数バックオフ）。
- JSONパース失敗時は`reasoning`含むエラーメッセージをSlackに送る（手動再実行）。

## 5. n8n WF-B: Analyze & Suggest Next Actions
### 5-1. 目的
- `status=published`の記事を分析し、改善案を生成しSlackに通知。必要ならWF-Aへ再投入。

### 5-2. ノード構成
1. Manual Trigger
2. Google Sheets - Get Published (`status=published`)
3. Function - Filter Published
4. Project Config B: `mdc_content`と`openai_api_key`
5. Merge Published + Config
6. OpenAI - Analyze Performance
   - モデル: `gpt-4o-mini`
   - 温度: 0.4 / top_p: 1 / max_tokens: 800
   - 期待JSON:
```json
{
  "next_decision": "improve|pause|scale",
  "next_action": "string",
  "next_segment": "Cold|Middle|Hot|Current",
  "next_keyword_idea": "string",
  "insights": ["bullet1", "bullet2"],
  "reasoning": "string"
}
```
7. Function - Parse JSON（スキーマ検証含む）
8. Google Sheets - Update Plan Row: `next_*`列を書き込み
9. Slack Notify - Analysis: 要約+承認ボタン

### 5-3. WF-B→WF-A再投入
- 承認後（Slack操作後）、新規行を`status=idea`として追加し、`trending_keyword=next_keyword_idea`、`abstract=next_action`、`segment=next_segment`をセット。既存行は`next_decision`に応じて維持。

## 6. Slack承認フロー
- チャンネル: `#content-ops`（仮）
- 投稿フォーマット（WF-A新ドラフト）:
```
[Draft Ready] {generated_title}
Segment: {segment} / Keyword: {trending_keyword}
Preview: {generated_body[0:200]}...
Actions: ✅ Approve | ❌ Reject (スレッドでキーワード)
RowID: {rowNumber}
```
- 投稿フォーマット（WF-B分析）:
```
[Analysis] {note_title or generated_title}
Decision: {next_decision}
Action: {next_action}
Next Segment: {next_segment}
Next Keyword: {next_keyword_idea}
Actions: ✅ Approve reinject | ❌ Ignore
RowID: {rowNumber}
```
- 承認操作: スレッド返信で`approve`/`reject`キーワードをWebhookで拾う（n8n Webhook + Filter）。承認時はSheets更新を実行。
- 反映先: WF-A承認→`status`を`draft-generated`から`published`へ更新（公開手動後）。WF-B承認→再投入用に新規`idea`行追加。

## 7. セグメント方針と決定ルール
- 値域: Cold / Middle / Hot / Current
- 初期値（WF-A）: 入力`segment`が空なら`Cold`をデフォルト。
- WF-B決定ロジック例: 
  - CV低 & PV低: Cold（認知不足）
  - PV高 & CV低: Middle（差別化訴求不足）
  - CV高: HotまたはCurrent（アップセル）

## 8. KPI定義とデータ取得
- `note_pv`: GA4 `screenPageViews`（対象ページ: note記事URL）。
- `note_likes`: note APIで取得できない場合、手動入力またはスクレイプバッチ（後続検討）。
- `note_conversion`: 「問い合わせ/メルマガ登録数」等のCV件数。計測はGA4イベント or note側計測が可能ならAPI連携。列コメントで定義明記。
- 更新頻度: 1日1回バッチ（n8n cron）でGA/GSCを参照してSheets更新する想定。

## 9. OpenAI I/Oとエラー処理
- APIキー: n8n Credentialsに保存（環境変数渡し禁止）。
- 共通パラメータ: `temperature`, `top_p`, `max_tokens`, `response_format=json`。
- JSONパース: Functionでsafe-parseし、必須キー欠落時はSlackにエラー通知。
- レート/コスト: 429/500系は最大3回リトライ、間隔2s/4s/8s。コスト監視はOpenAI Usage APIを週次チェック。

## 10. セキュリティとクレデンシャル管理
- OpenAI/Slack/Webhook/Sheetsのクレデンシャルはすべてn8n Credentialsに保存し、Gitに含めない。
- note自動投稿を行う場合は別Credentialを作成し権限を最小化。
- Webhookには署名検証 or トークン検証を付与。Slack返信Webhookも同様。
- `.mdc`は公開リポにあるため、機微情報は含めない（思想・ルールのみ）。
