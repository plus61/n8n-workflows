# ワークフロー一覧

## 📂 ディレクトリ構成

各ワークフローは独立したディレクトリで管理されています:

```
workflows/
├── line-crm/              # LINE CRM統合ワークフロー
├── notion-integration/    # Notion統合ワークフロー
└── templates/            # 再利用可能なテンプレート
```

## 📋 各ワークフローの詳細

各ディレクトリ内の`README.md`に以下の情報が記載されています:

- **概要**: ワークフローの目的と機能
- **設計思想**: なぜこの設計にしたのか
- **セットアップ**: 導入手順
- **設定項目**: 必要な認証情報や環境変数
- **使用例**: 実際の使い方
- **トラブルシューティング**: よくある問題と解決方法

## 🚀 クイックスタート

1. 使いたいワークフローのディレクトリに移動
2. `README.md`を読んで概要を把握
3. `.json`ファイルをn8nにインポート
4. 必要な認証情報を設定
5. テストを実行

## 💡 ベストプラクティス

詳細は [docs/best-practices.md](../docs/best-practices.md) を参照してください。

### ワークフロー作成時

- ✅ エラーハンドリングを必ず実装
- ✅ ログ出力を適切に設定
- ✅ 環境変数で認証情報を管理
- ✅ ノード名をわかりやすく命名
- ✅ コメントで処理内容を記載

### 運用時

- ✅ 定期的にログを確認
- ✅ エラー発生時は即座に対応
- ✅ **検証完了後は必ずバックアップを取得** → [バックアップポリシー](../docs/workflow-backup-policy.md)
- ✅ 変更前にバックアップを取得
- ✅ テスト環境で動作確認
- ✅ ドキュメントを最新に保つ

## 🔧 カスタマイズ

ワークフローは自由にカスタマイズできます:

1. **ノードの追加**: 新しい処理を追加
2. **条件分岐の変更**: ビジネスロジックに合わせて調整
3. **通知先の変更**: Slack、Email等に変更可能
4. **データ形式の変更**: 必要な項目を追加・削除

カスタマイズ後は、変更内容をドキュメントに記録することをお勧めします。

## 📞 サポート

問題が発生した場合:

1. 各ワークフローの`troubleshooting.md`を確認
2. [docs/troubleshooting.md](../docs/troubleshooting.md)を確認
3. GitHubのIssueで質問
